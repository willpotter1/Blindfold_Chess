## Design Context

### Users
Chess players of all levels who want to train blindfold visualization skills. They come to practice — playing games, solving puzzles, running drills, studying openings — all without seeing the board. The interface should stay out of the way and let them focus.

### Brand Personality
Calm, sleek, distinctive. Not boring like the major chess sites, but not flashy either. A quiet confidence — like a well-made object you enjoy using.

### Aesthetic Direction
- **Visual tone:** Minimal and modern. Clean surfaces, generous spacing, sharp typography. No gradients, no visual noise, no layered effects.
- **Color palette:** Dark mode default with warm neutral grays (subtle R > G > B warm undertone that echoes the chess board's wood tones). Custom palette tokens prefixed `--cl-` (void, obsidian, coal, graphite, iron, slate, ash, silver, pearl, snow, white). Not pure/cold gray, not muddy brown.
- **Theme:** Dark mode default (`:root`), light mode opt-in via `.light` class on `<html>`.
- **Anti-references:** Muddy gradients, over-decorated surfaces, the generic look of most chess sites. Nothing that looks like it was built from a template.
- **Typography:** Manrope (sans-serif) for body text. Lora (serif) for h1 headings only — used sparingly for major display text.

### Design Principles
1. **Quiet confidence** — The interface should feel assured and refined without trying too hard. No decoration for its own sake.
2. **Content over chrome** — The chess board and game state are the main event. Everything else supports them.
3. **Flat and clean** — No gradients, no layered radial glows, no paper-grain textures. Solid colors, crisp borders, clear hierarchy.
4. **Breathe** — Generous spacing. Let elements have room. Dense information panels are fine, but they need visual breathing room around them.
5. **Warm, not sterile** — Grays carry a subtle warm undertone that harmonizes with the chess board's wood tones. Not cold, not muddy.

### Component Patterns
- **Borders:** `border border-border/50` — thin, subtle. Never `border-2`.
- **Cards:** `rounded-xl border border-border/50 bg-card shadow-theme-soft` via the base Card component.
- **Focus rings:** `focus-visible:ring-2 focus-visible:ring-foreground/20` — 2px ring, no offset. Inputs also brighten border on focus (`focus-visible:border-foreground/25`).
- **Inputs:** Default `h-10 rounded-lg border border-border/50 bg-card text-base md:text-sm`. Placeholder: `text-muted-foreground/60`. Browser autofill overridden globally with `-webkit-box-shadow` inset to match card bg, `-webkit-text-fill-color` for foreground color.
- **Buttons:** Icons from lucide-react. Primary actions use `bg-primary`, secondary use `border border-border/50 bg-card hover:bg-secondary`. Game-over actions: primary has `RotateCcw`, secondary has `Settings`. Export actions grouped in a card with section label, using `ExternalLink`, `Copy`, `Download` icons.
- **Number inputs:** Use custom `NumberInput` component (`src/components/ui/number-input.tsx`) with styled chevron up/down buttons. Native browser spinners are hidden globally via CSS. Inline validation errors shown in `text-xs text-destructive` below the input.
- **Toggle switches:** Inline `<label>` wrapping Switch + text, using `flex-wrap` for responsive flow. No bordered card containers around toggles.
- **Selection chips:** Compact clickable chips with `X` icon for removal, `flex-wrap` layout, `overflow-y-auto` for scroll when many selected.
- **Interactive elements:** All get `cursor-pointer` via global base rule targeting `button`, `[role="button"]`, `[role="menuitem"]`, `[role="option"]`, `[role="tab"]`, `a[href]`, etc.
- **Animations:** `animate-fade-up` (translateY entrance), `animate-scale-in` (scale entrance), `animate-fade-in` (opacity). Staggered with `delay-0` through `delay-700` at 100ms steps. Spring easing: `cubic-bezier(0.16, 1, 0.3, 1)`.
- **Shadows:** `--shadow-soft` for cards/general, `--shadow-strong` for elevated elements (3D board, popovers). `--shadow-piece` for chess pieces.
- **Keyboard shortcuts:** Global spacebar hold-to-reveal board during active game/puzzle/opening sessions. Skips when focus is in INPUT/TEXTAREA/SELECT. Show Board button displays `Space` kbd badge inline.

### Navigation
- **Desktop (>=768px):** Compact vertical icon sidebar (`w-20`) with lucide icons (Puzzle, Target, BookOpen) + labels. Sticky left. Active route: `bg-secondary`. Sign Up button: outlined with `border border-border/50` (not filled) to distinguish from active state. Auth at bottom: LogIn, UserPlus icons.
- **Mobile (<768px):** Sticky top navbar (solid `bg-background`, no backdrop blur) with hamburger + logo left, auth buttons right. Sign Up: outlined `border border-foreground/20`. Hamburger opens a slide-out side panel with animated backdrop blur (300ms `ease-out`). Active route highlighted with `bg-secondary`. Panel auto-closes on navigation.

### Layout
- Use Tailwind classes exclusively — no inline pixel styles for layout, no `useDesktopFitLayout` pixel computation hooks. Board sizes via `max-w-[min(75vh,700px)]` / `xl:max-w-[min(80vh,780px)]`.
- Responsive grid: `lg:grid-cols-[minmax(0,1.4fr)_minmax(0,1fr)]` for board + panel (home, puzzles). `lg:grid-cols-[minmax(0,1fr)_minmax(0,1fr)]` for openings (equal split — wider panel needed). `lg:grid-cols-[minmax(0,1.8fr)_minmax(0,1fr)]` for drills (larger board).
- Desktop game panel: single column stack (participants side-by-side at top → status → controls → move history as flex-1). No side-by-side controls+history layout (causes shift).
- Landing page scales: `max-w-5xl xl:max-w-6xl`, gaps `lg:gap-10 xl:gap-14`, padding `lg:py-10 xl:py-16`.
- 3D board: hidden on mobile (`hidden lg:flex`), `bg-card` container for loading state visibility. Canvas cleanup on unmount. Initial tree focus skipped to prevent page scroll (`hasUserInteractedRef`).
- Mobile/tablet: board + panel in single column. `max-w-xl` default, `md:max-w-2xl` for puzzles/drills, `md:max-w-3xl` for openings.
- Openings page: uses `md:flex-row` for sidebar but content stays mobile-style single column until `lg`. No `useDesktopGameLayout` hook — pure Tailwind breakpoints.
- Auth pages (login, signup): centered `max-w-sm` form, no Card wrapper. Icon + title header. Vertically centered on desktop (`md:items-center`).

### Cross-Browser
- No `dvh` units — use `vh` everywhere.
- No arbitrary media queries — use Tailwind breakpoints (`max-md:`, `lg:`, `xl:`).
- Animation keyframes include `-webkit-transform` prefixes.
- Native number input spinners hidden globally (`-webkit-appearance: none`, `-moz-appearance: textfield`).
- Browser autofill background overridden via `-webkit-box-shadow` inset + `-webkit-text-fill-color` + delayed `transition`.
- `@supports not (backdrop-filter)` fallback for opaque backgrounds.
- `viewport-fit=cover` in viewport meta for notch support.
- `text-wrap: balance` is progressive enhancement (no fallback needed).

### SEO
- Favicons: `Whitepawn.png` for browser tabs (visible on dark tabs), `circlepawnwb-*.png` for Google search results / manifests (visible on white backgrounds).
- Web manifest at `public/site.webmanifest` with dark theme color.
- Structured data: WebSite (with alternateName variants) + WebApplication (with featureList, free pricing) + FAQPage schemas.
- Per-page SEO via `SeoHead` component with unique titles, descriptions, and canonical URLs.
- Keywords target: blindchess, blind chess, blindfold chess, chess visualization, chess trainer.

### Session URLs
- Active sessions get UUID-based URLs: `/game/{uuid}`, `/puzzles/{uuid}`, `/drills/{uuid}`, `/openings/{uuid}`.
- Generated client-side via `crypto.randomUUID()` on session start.
- Stale session URLs (no in-memory state) redirect to base route.
- UUID always shown for all users; only persisted to Supabase for authenticated users.
